# 前端高级技术清单

> 适用范围：现代浏览器（2026 年），重点关注与音视频、实时流、高性能计算相关的 API。

## 一、音视频与实时流（与 FLV/直播项目最相关）

- **MediaSource Extensions（MSE）**：把 `BufferSource` 喂给 `<video>`，由浏览器管理 buffer、追帧、拼接。HLS / DASH 播放器基本都基于这套。
- **Encrypted Media Extensions（EME）**：配合 MSE 实现 DRM（Widevine、PlayReady、FairPlay）。
- **WebTransport**：基于 HTTP/3（QUIC）的双向低延迟通道，可替代 `WebSocket` + 自定义协议。比 `fetch` 流式响应更可控。结合 WebCodecs 是 LL-HLS / MoQ（Media over QUIC）的雏形。
- **WebRTC**：端到端实时通信。配合 **Insertable Streams** 和 **Encoded Transform** 可以在 SRTP 加密前后插入自定义处理（自定义加密 / SFrame、注入 SFU 元数据、端上滤镜）。
- **WebCodecs + WebTransport + WebGPU**：当下做浏览器内超低延迟直播 / 实时音视频处理的"黄金三角"。

## 二、计算与并行

- **Web Workers + SharedArrayBuffer + Atomics**：多线程共享内存，配合 `Atomics.wait/notify` 做无锁队列。
- **OffscreenCanvas**：把 Canvas 渲染移到 Worker，不阻塞主线程；与 WebCodecs 的 `VideoFrame` 直接对接。
- **WebAssembly 进阶特性**：threads、SIMD、bulk memory、reference types、GC 提案、异常处理提案。FLV 这类二进制解析用 WASM SIMD 比纯 JS 快一个数量级。
- **WebGPU Compute Shaders**：通用 GPU 计算，可做视频帧前/后处理、滤镜、shader-based 处理、编码前预处理。

## 三、存储与持久化

- **OPFS（Origin Private File System）**：浏览器私有文件系统，配合 Workers 异步 API 可做高性能落盘（录制、缓存、边播边存）。
- **Storage Buckets API**：把 IndexedDB / CacheStorage / OPFS 按"桶"隔离，避免一个站点单一存储被回收。
- **IndexedDB**：老牌结构化存储，事务化 + 异步。

## 四、硬件与外设

- **WebUSB / WebSerial / WebHID / WebBluetooth / WebNFC / WebMIDI**：直连硬件设备。对播放器场景意味着可以接采集卡、串口控制 PTZ、蓝牙遥控等。
- **Gamepad API**：遥控 / 手柄输入。
- **Sensor APIs**：Accelerometer / Gyroscope / Magnetometer / Ambient Light Sensor 等，XR 场景有用。
- **Screen Wake Lock API**：保持屏幕常亮，播放 / 直播必备。
- **File System Access API**：用户授权后读写本地文件。
- **Pointer Lock API**：锁定鼠标用于游戏 / 全景视频。

## 五、图形与 UI

- **CSS Houdini**（Paint API / Layout API / Typed OM / Properties & Values API）：把 CSS 引擎暴露给 JS，做自定义绘制与动画，比 Canvas 更高效。
- **View Transitions API**：SPA 路由过渡动画，含跨文档版本。
- **Anchor Positioning** + **`@starting-style`** + **`transition-behavior: allow-discrete`**：CSS 新布局与动画原语。
- **Scroll-driven Animations**：滚动驱动动画，性能优于 JS 方案。
- **WebXR**：VR / AR 设备接入。
- **EyeDropper API**：拾色器。
- **Document Picture-in-Picture**：把任意 HTML 元素放到画中画窗口，播放器场景可做"画中画弹幕"。

## 六、AI / ML 推理

- **WebGPU / WebGL** 作为底层加速。
- **WebNN API**（Web Neural Network API，正在推进）：直接调用设备 NPU / NNAPI / Core ML，比 WebGPU 更省电。
- **生态**：Transformers.js、ONNX Runtime Web、MediaPipe Tasks、TensorFlow.js 等上层封装。

## 七、安全与认证

- **Web Crypto API**：`SubtleCrypto` 做对称 / 非对称加解密、签名、密钥派生，可用于 FLV 流的端上解密。
- **WebAuthn**：无密码登录、硬件密钥。
- **Credential Management API**：统一管理密码 / Passkey / 联邦登录。
- **Permissions API**：把权限申请抽象成一致模式。
- **Trusted Types**：防 XSS。
- **CSP（CSP Level 3）**：细粒度资源加载限制。

## 八、流式与异步原语

- **Streams API**（`ReadableStream` / `WritableStream` / `TransformStream`）：FLV 解封装天然适合用 TransformStream 串成 pipeline —— 输入字节流 → 解 tag → 输出 chunk 流，下游直接给 WebCodecs。
- **Compression Streams API**：原生 gzip / deflate / brotli 流式压缩，可用于缓存层。
- **EventSource / WebSocket**：SSE 与双向消息。
- **Task Controller / Scheduler APIs**（部分提案中）：更灵活地调度任务优先级。

## 九、其他常被忽视但极有用的 API

- **Custom Elements + Shadow DOM（Web Components）**：与框架解耦的组件原语。
- **Import Maps**：去掉打包步骤，原生 ESM 直接用 npm 包。
- **Intl 增强**：`Intl.Segmenter`（分词）、`Intl.RelativeTimeFormat`、`Intl.NumberFormat` 单位格式化等。
- **Web Share API / Clipboard API**：分享与剪贴板。
- **Payment Request API**：标准化支付。
- **Storage Manager**：估算配额。
- **WebSocket Streams**：把 WebSocket 接入 Streams API 体系（部分浏览器已支持）。
- **Broadcast Channel API**：跨同源上下文（tab / worker）通信。
- **Channel Messaging API**：`MessageChannel` 实现无依赖双向通信。

## 十、对 FLV 播放器项目的推荐方向

按"投入产出比"排序：

1. **Streams API 串起 FLV → EncodedChunk → WebCodecs 整条 pipeline**：架构最干净，性能也好。
2. **WebTransport 替换 WebSocket**：延迟更低，原生支持乱序与多路复用。
3. **WASM + SIMD** 重写 hot path（tag 解析、AVC / HEVC Annex-B / AVCC 头解析）：能跑出接近 native 的速度。
4. **WebGPU Compute Shader** 做视频帧后处理（缩放、色彩空间转换、HDR tone mapping、字幕叠加）：比 Canvas / WebGL 更现代。
5. **SharedArrayBuffer + Atomics**：在主线程与 Worker 之间零拷贝传递帧指针。
6. **OPFS**：把缓存切片持久化，便于断线续播。
7. **WebCodecs + Insertable Streams** 接入 WebRTC 时，可以把 FLV 流直接送进 SFU。
8. **OffscreenCanvas + WebCodecs**：在 Worker 里完成解码 → 渲染，不卡主线程。
9. **WebGPU Video Processor**：用 WGSL 直接对 `VideoFrame` 做色彩转换 / 缩放，作为零拷贝路径上 GPU 渲染前的最后一环。
