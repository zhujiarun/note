# 理解 C++ 栈和堆

> 前置阅读：[[理解C++指针]] —— 指针是一张"门牌号"，而栈和堆就是两种不同风格的"街区"。

---

C++ 程序运行时，内存主要分为两大区域——**栈（stack）** 和**堆（heap）**。它们的分配方式、生命周期、性能特征完全不同，但又共同支撑着整个程序的内存运转。

延续指针笔记的"门牌号"模型：**栈是一个自动整理停车的代客泊车区，堆是一个自己找车位自己还钥匙的自助停车场。**

---

## 栈（Stack）

### 什么是栈

栈是一块按 **后进先出（LIFO）** 顺序管理的内存区域。每次调用函数，编译器会在栈顶压入一块空间（称为**栈帧**，stack frame），用来存放函数的局部变量、参数和返回地址。函数返回时，这块空间自动弹出，局部变量随之销毁。

```cpp
void foo() {
    int x = 42;   // x 在栈上分配
    char c = 'a'; // c 也在栈上，紧挨着 x
}                 // 出作用域，x 和 c 自动释放

void bar() {
    foo();        // 调用 foo 时压栈，返回时弹栈
    int y = 0;    // y 在栈上，但和 foo 里的 x 用的是同一块内存（地址可能相同）
}
```

**关键特征：**

- **自动分配自动释放**——不需要手动 `delete`，出作用域就没了。
- **速度极快**——分配就是移动一个栈顶指针（`rsp` 寄存器做加法），开销几乎为零。
- **大小有限**——典型栈大小是 **1MB ~ 8MB**（取决于平台和编译器设置）。太大就栈溢出了。
- **局部性极好**——连续分配的数据在物理上也连续，CPU 缓存友好。

### 栈的生命周期 = 作用域

```cpp
int* dangling() {
    int local = 42;
    return &local;  // 危险！返回了栈上变量的地址
}                   // local 已被销毁，指针悬垂
```

这是栈和指针最经典的碰撞——返回栈变量的地址，得到的就是**悬垂指针**（dangling pointer）。门牌号还在，但那个房子已经被拆了。这也是为什么函数不能返回局部变量的地址或引用。

### 谁在栈上？

- 局部变量（包括 `int`、`double`、数组、对象）
- 函数参数和返回值
- 函数调用的返回地址（控制流用，程序员不直接看到）

```cpp
void func(std::string s) {  // s 本身在栈上
    int arr[100];            // arr 整个数组在栈上（100 * 4 = 400 字节）
    std::string t = "hi";    // t 对象本身在栈上，但 t 内部的字符数据呢？
}                            // 这取决于 std::string 的实现——见下文 SSO
```

## 堆（Heap）

### 什么是堆

堆是一块供程序**动态**分配和释放的内存区域。编译器不知道你需要多少空间、要存活多久——这些信息只有运行时的代码逻辑才知道。

```cpp
void heap_example() {
    int* p = new int(42);           // 在堆上分配一个 int
    int* arr = new int[1000];       // 在堆上分配 1000 个 int
    // 用完之后...
    delete p;                       // 手动释放
    delete[] arr;                   // 注意数组要用 delete[]
}
```

**关键特征：**

- **手动管理**——用 `new` 分配，用 `delete` 释放。忘了删就是内存泄漏。
- **速度较慢**——分配需要在堆的空闲块列表中查找一块足够大的空间，涉及系统调用（`malloc` → `brk`/`mmap`），开销远大于栈分配。
- **空间巨大**——堆的大小只受系统可用内存和地址空间的限制，通常可以分配 GB 级别的内存。
- **生命周期灵活**——只要不 `delete`，堆上分配的对象就一直活着，不限于分配它的函数作用域。

### 堆的生命周期由你决定

```cpp
int* create_array(int n) {
    int* arr = new int[n];  // 堆分配
    return arr;             // 安全！堆上的内存在函数返回后依然存在
}

void user() {
    int* data = create_array(1000);
    // 用 data...
    delete[] data;          // 你要记得释放——create_array 不负责
}
```

这也呼应了指针笔记中说的：指针本身只是一个存了门牌号的变量，至于这个门牌号指向的是栈地址还是堆地址，它不区分，也没法区分。**指针不告诉你地址来自哪个区域，这是你的责任。**

### 谁在堆上？

- `new` / `new[]` 分配的所有对象
- `malloc` / `calloc` / `realloc` 分配的所有内存（C 风格）
- 标准容器的内部数据（`std::vector`、`std::string`、`std::map` 等**元素存储**在堆上，容器对象本身在栈上）

```cpp
void container_example() {
    std::vector<int> v;        // v 本身：栈上（一个很小的控制块，通常 24 字节）
    v.push_back(42);           // v 的数据区：堆上（元素实际存储的地方）
}                              // v 出作用域，析构函数自动释放堆上的数据
```

这里有一个重要但容易误解的点：**容器对象本身在栈上，容器内部的数据在堆上。** `std::vector` 的栈上部分只存了三个指针（`begin`、`end`、`capacity`），真正存元素的大块内存在堆上。这也是为什么 `std::vector` 可以安全地作为局部变量返回——它用移动语义"偷走"了那个堆指针，而不需要拷贝底下的数组。

## 对比总览

| 维度 | 栈（Stack） | 堆（Heap） |
|------|-----------|-----------|
| **分配方式** | 编译器自动压栈/弹栈 | 程序员手动 `new`/`delete` |
| **速度** | 极快（寄存器加减） | 较慢（查空闲链表 + 可能系统调用） |
| **大小** | 很小（通常 1~8 MB） | 很大（受限于系统内存） |
| **生命周期** | 绑定到作用域 | 由程序员控制，直到 `delete` |
| **碎片化** | 天然无碎片 | 反复分配释放会产生碎片 |
| **典型用途** | 局部变量、函数调用 | 大块数据、长生命周期对象 |
| **出问题** | 栈溢出（递归太深 / 局部数组太大） | 内存泄漏 / 悬垂指针 / 野指针 |

## C++17 视角的延伸

### SSO（Small String Optimization）—— 栈和堆的分水岭

`std::string` 内部有一个"小字符串优化"：如果字符串很短（不同实现阈值不同，通常是 15~22 字节），字符数据直接存在栈上（`std::string` 对象内部的一个小数组里）；超过阈值，才去堆上分配。

```cpp
std::string s1 = "hi";           // 短 → 存在栈上（在 s1 对象内部）
std::string s2 = "hello world this is a long string";  // 长 → 去堆上分配
```

这意味着：
- 大多数短字符串的操作**不涉及堆分配**，速度极快。
- 拷贝短字符串是纯栈操作（拷贝对象内部的小数组），而长字符串拷贝要访问堆，速度和前者差几个数量级。
- 从指针视角看：当字符串在栈上时，`s.c_str()` 返回的是栈地址；在堆上时，返回的是堆地址。但作为调用者，你不需要关心——`string` 把这些细节封装了。

这也是为什么**按值传 `std::string` 不一定是坏事**——如果字符串短，它根本没碰堆。

### `std::optional<T>` 和 `std::variant<T...>` —— 纯栈工具

这两个 C++17 类型**从来不使用堆**：

```cpp
std::optional<int> o;           // 栈上，只占 sizeof(int) + 1 字节
std::variant<int, double> v;    // 栈上，占 max(sizeof(int), sizeof(double)) + 类型标记
```

- `optional` 就是栈上的一个 `T` + 一个布尔标志。
- `variant` 就是栈上的一块空间（足够容纳所有可能类型中最大的那个）+ 一个类型索引。

它们的价值在于**不需要堆分配就能表达"多态"或"可选"的语义**。过去你可能用 `T*`（需要堆分配或指向已有的堆对象）来表达"可能为空"，现在 `optional` 在栈上就完成了这件事。

### `std::unique_ptr` —— 栈上的控制块，堆上的数据

```cpp
void demo() {
    auto p = std::make_unique<int>(42);
    // p 本身（unique_ptr 对象）在栈上，占 8 字节（一个指针）
    // p 指向的 int 在堆上
    // p 出作用域时，析构函数自动 delete 堆上的 int
}
```

`unique_ptr` 对象本身在栈上（就是包了一个裸指针），它指向的对象在堆上。它是**连接栈和堆两套生命周期规则**的桥梁——栈的自动析构机制驱动堆内存的自动释放。

## 如何判断一个变量在栈上还是堆上？

```cpp
int  a = 42;                 // 栈
int* b = new int(42);        // b 本身在栈上，*b 在堆上
int  c[10];                  // 栈（整个数组在栈上）
int* d = new int[10];        // d 在栈上，d[0..9] 在堆上

std::string s = "hello";     // s 在栈上；字符数据：短则在栈，长则在堆
std::vector<int> v(100);     // v 在栈上；100 个 int 在堆上

static int e = 42;           // 既不在栈也不在堆——在静态存储区

int* f = &a;                 // f 在栈上，f 存的是栈地址
int* g = b;                  // g 在栈上，g 存的是堆地址
                             // f 和 g 的类型都是 int*，说明指针不区分来源
```

判断的关键规则：**对象本身的存储位置由它的声明方式决定，而不是由它内部的数据决定。**

## 总结

- **栈**是自动管理的 LIFO 区域——速度快、空间小、出作用域自动释放。局部变量默认在栈上。
- **堆**是手动管理的动态区域——速度慢、空间大、生命周期灵活。`new`/`malloc` 出来的内存在堆上。
- **指针不区分栈地址和堆地址**——`int*` 可以指向栈上的变量，也可以指向堆上的对象。这意味着一不小心就会写出悬垂指针（指向已释放的栈内存）或野指针（指向已释放的堆内存）。
- **C++17 的工具帮你做选择**：`optional` 和 `variant` 让你在栈上解决问题，避免不必要的堆分配；`string_view` 让你安全地"看一眼"别人栈上或堆上的字符串而不拥有它；智能指针则用栈上的对象管理堆上的内存，把两套生命周期规则缝合在一起。

如果回到最开始的两个比喻——**代客泊车区（栈）** 和**自助停车场（堆）**——核心区别不在于车位本身，而在于"谁负责什么时候把车开走"。栈由编译器代劳，堆由你亲自来。
