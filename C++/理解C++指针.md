# 理解 C++ 指针

## 指针的核心概念：门牌号模型

理解 C++ 指针，最有效的方式是从"内存模型"这个角度切入。

### 指针本质上就是一个存了门牌号的整数

把内存想象成一条很长很长的街道，每个字节就是一个门牌号。声明一个变量 `int a = 42;`，编译器就在这条街上找一块空地（比如门牌号 0x1000 到 0x1003，int 占 4 个字节），在里面存下 42。而指针 `int* p = &a;` 做的事情极其简单：它自己也是一块内存，里面存的不是 42，而是门牌号 0x1000。

变量 `a` 的地址是 0x1000，而 `p` 里存的就是 0x1000。这是理解指针最关键的一步——**指针变量里装的是另一个变量的地址**。

### 两个核心操作：`&` 和 `*`

- `&a`（取地址）：问的是"你的门牌号是多少"，返回一个地址值。
- `*p`（解引用）：问的是"你指的那个房子里面放了什么"，顺着门牌号找过去，把里面的值拿出来——或者往里写新值。

所以 `*p = 100;` 并没有修改 p 本身，p 里还是 0x1000，但它指过去的那块内存里的内容变成了 100。`a` 也就同步变成了 100，因为它们本来就是同一块内存。

### 指针的类型为什么重要

如果指针只是存一个门牌号，为什么要有类型区分？因为光知道从哪扇门进去还不够——你还得知道这栋房子占几间（几个字节），以及里面的东西该怎么解读。

- `int*`：从这扇门进去，往后数 4 个字节，按有符号整数的规则解读。
- `double*`：往后数 8 个字节，按浮点规则解读。
- `char*`：只读 1 个字节。

所以 `p + 1` 不是门牌号加 1，而是跳过一个完整元素——`int*` 的 `+1` 实际地址偏移了 4 个字节。

### 指针和数组的关系

数组名在大多数表达式中会退化为指向首元素的指针。`int arr[5];` 中，`arr` 本身不是一个指针变量（它没有自己的独立存储位置来存地址），但当你写 `arr + 2` 或者把 `arr` 传给一个接受 `int*` 的函数时，它就退化成了指向 `arr[0]` 的指针。`arr[2]` 和 `*(arr + 2)` 是等价的——方括号本质上就是**语法糖**。

#### 语法糖

"语法糖"（syntactic sugar）指的是不增加新能力、只是让代码写起来更舒服的语法形式。它的底层语义和另一种更原始的写法完全等价。

`arr[2]` 在编译期直接被翻译成 `*(arr + 2)`，二者编译后生成的机器码一模一样。这也是为什么可以写出这种合法的代码：

```cpp
int arr[5] = {1, 2, 3, 4, 5};
std::cout << 2[arr];        // 输出 3
```

因为 `2[arr]` 被编译器翻译成 `*(2 + arr)`，而加法交换律下 `*(2 + arr)` 和 `*(arr + 2)` 是一样的，也就是 `arr[2]`。如果没有方括号这个语法糖，人们就只能用指针加法和解引用来访问数组元素。有了它，数组访问看起来像一个专门的操作，但实际上从头到尾都是指针运算。

### 动态内存

栈上的变量出了作用域就自动销毁，但 `new` 出来的内存在堆上，必须手动 `delete`。这时候必须用指针来记住那块内存的地址，否则就永远找不回来了——这就是内存泄漏。

#### `nullptr`（C++11）—— 类型安全的空指针

C++11 之前，空指针用 `NULL` 或 `0` 表示。问题是 `NULL` 在大部分实现中被定义为 `0` 或 `(void*)0`，这导致了一个经典歧义：

```cpp
void f(int);
void f(char*);

f(NULL);  // 调用 f(int) 还是 f(char*)？—— 取决于实现，很可能调了 f(int)
```

`nullptr` 的类型是 `std::nullptr_t`，它可以隐式转换为任何指针类型，但不能转为整数。所以 `f(nullptr)` 毫无歧义地调用 `f(char*)`。

在"门牌号"模型下，`nullptr` 就是一张写着"空"的门牌——它不指向任何合法地址。解引用 `nullptr` 是未定义行为，绝大多数平台会直接崩溃（segment fault），这比解引用一个野指针要好得多——野指针可能"碰巧"指向一块合法的内存，导致 bug 潜伏很久才暴露。

#### 智能指针（C++11）—— 带所有权的指针封装

指针本身只存地址，不负责生命周期。谁来释放 `new` 出来的内存？谁最后一个不用了就负责清理？这就是**所有权**问题。智能指针把"释放内存"这个动作绑定到对象的析构函数里，让编译器替你调用 `delete`。

**`std::unique_ptr<T>` —— 独占所有权**

```cpp
std::unique_ptr<int> p = std::make_unique<int>(42);
// 不需要 delete，p 出作用域时自动释放
```

- 唯一拥有指向的对象，不能拷贝（拷贝构造被 `= delete` 了），只能移动。
- 移动后原指针变成 `nullptr`，所有权转移。
- 性能几乎和裸指针一样（没有额外开销）。
- 对应"门牌号"模型：一个门牌号只能有一个人拿着钥匙，钥匙可以转交（移动），但不能复制。

**`std::shared_ptr<T>` —— 共享所有权**

```cpp
std::shared_ptr<int> p1 = std::make_shared<int>(42);
{
    std::shared_ptr<int> p2 = p1;  // 引用计数 +1，现在是 2
    // 出作用域，p2 销毁，引用计数 -1
}
// 此时引用计数回到 1，p1 销毁时释放内存
```

- 内部维护一个引用计数（control block），每一次拷贝增加计数，每一次析构减少计数。
- 计数归零时自动 `delete` 对象。
- 代价：引用计数的增减是原子操作，有额外性能开销；control block 需要额外分配内存。

**`std::weak_ptr<T>` —— 旁观者**

```cpp
std::weak_ptr<int> wp = p1;  // 不增加引用计数
if (auto sp = wp.lock()) {   // 尝试提升为 shared_ptr
    // 对象还活着，安全使用
} else {
    // 对象已被释放
}
```

- 解决 `shared_ptr` 相互引用导致的内存泄漏（循环引用）。
- 不参与引用计数，只是"观察"对象是否还活着。
- 使用时通过 `.lock()` 尝试提升为 `shared_ptr`，如果对象已死则返回空。

**为什么用 `make_shared` / `make_unique`？**

```cpp
auto p = std::make_shared<int>(42);   // 推荐
std::shared_ptr<int> p(new int(42));  // 不推荐
```

- 异常安全：`make_shared` 把对象和 control block 一次性分配，没有中间状态。
- 性能更好：少一次内存分配。
- 但 `make_shared` 不支持自定义删除器，这种情况下才需要用 `new`。

回到"门牌号"模型：智能指针不是一种新概念，它就是在指针外面包了一层对象，利用 C++ 的构造和析构机制来注入"什么时候释放"的规则。指针的核心机制——存地址、解引用、偏移——全部没变。变的只是"谁负责清理"这个问题的答案从程序员变成了编译器。

## 引用（Reference）

引用在底层通常就是指针——编译器帮你自动加了 `*` 解引用而已。写 `int& r = a;` 之后，用 `r` 就像用 `a` 本尊一样，不用写 `*r`，不用关心地址。但编译器生成的代码，很可能和 `int* const p = &a;` 然后每次用 `*p` 是一样的逻辑。

### 引用和指针的核心差异

差异不在实现，在语义层面：

- 引用不允许为空（不存在"不指向任何东西的引用"）。
- 引用不允许改指向（一旦绑定了 a，一辈子就是 a）。
- 引用的语法更干净（赋值就是赋值，不会让人疑惑你在改指向还是改内容）。

现代 C++ 里，能用引用解决的场景（比如函数传参、范围 for 循环）就用引用，引用解决不了的（比如需要重新指向另一个对象、或者需要表达"可能没有值"），才用指针。

## 函数指针

既然指针可以存变量的地址，那同样也可以存函数的地址。函数编译后就是一段机器码躺在内存里，自然也有门牌号。

比如有一个函数 `void hello(int n)`，那么 `&hello` 就是它的地址——虽然通常可以省略 `&`，直接写 `hello`。要存储这个地址，需要一个匹配的指针类型：

```cpp
void (*p)(int) = hello;
```

这个声明读法：`p` 是一个指针，指向一个接受 int、返回 void 的函数。跟变量指针对照着看就不那么陌生了——`int*` 指向 int，`void(*)(int)` 指向某种函数，类比结构是一样的。

调用的时候写 `p(42)` 或者 `(*p)(42)` 都行，效果一样。函数指针的最大价值是回调（callback）——把一段行为像数据一样传来传去。C 的 `qsort` 就是一个典型例子，传一个比较函数的指针进去，`qsort` 不需要知道你在比较什么类型的东西，只管调用它。

现代 C++ 中纯函数指针用得少了，因为 `std::function`、lambda 表达式、模板都可以做同样的事且更灵活，但理解函数指针能帮助理解这些机制在底层干了什么。

## 多级指针

如果指针是"存着别人地址的变量"，那二级指针就是"存着指针地址的指针"。画出来就是一条链：

```
int a = 42;       // a 住在 0x1000，值 = 42
int* p = &a;      // p 住在 0x2000，值 = 0x1000
int** pp = &p;    // pp 住在 0x3000，值 = 0x2000
```

`pp` 的三个层次分别对应三种操作：

```cpp
std::cout << pp;    // 输出 0x2000 —— pp 变量里存的东西，也就是 p 的地址
std::cout << *pp;   // 输出 0x1000 —— 顺着 0x2000 找到 p，p 里存的是 a 的地址
std::cout << **pp;  // 输出 42     —— 再顺着 0x1000 找到 a，a 里存的是 42
```

### 使用场景

- 函数里要修改外部的一个指针变量。比如在函数内部分配内存并让外面的指针指过去，光传指针不够——那只能改指针指向的内容，改不了指针本身。得传指针的指针（或指针的引用），才能让函数内部改写外层的指针变量。
- 多维动态数组。`int**` 可以指向一个指针数组，每个元素再各自指着一块整数数组，这是模拟二维数组的常见手法。

多于二级的指针在实践中已经很少见了——三层以上的间接寻址通常意味着数据结构设计有问题，应该用结构体或类来整理层次。

## C++17 新特性中的指针延伸

C++17 没有直接修改指针的底层机制，但引入了几个和指针思想密切相关的工具——它们要么是"指针式思维"的体现（非拥有视图），要么是"指针语义"的安全替代品。

### `std::string_view` —— 非拥有字符串指针的现代化身

```cpp
#include <string_view>

void process(std::string_view sv) {
    for (char c : sv) { /* 只读访问 */ }
}

process("hello");              // const char* 隐式构造
process(std::string("abc"));   // std::string 隐式构造
```

`string_view` 本质上就是 `const char*` + `size_t` 的封装——存一个起始地址和一个长度，不拥有底层数据，不参与生命周期管理。

把它和你的笔记对照看：
- 它就和 `const char*` 一样是"只看不拥有"的——调用者必须保证底层 buffer 在 `string_view` 使用期间活着。
- 但它比 `const char*` 多了一个"我知道自己有多长"的信息，所以不会遇到需要 `strlen` 才能知道长度的问题，也不会踩到缺少 `\0` 终结符的 buffer。
- 因为不拥有，它的拷贝是 O(1) 的——拷贝一个 `string_view` 只是复制了地址和长度两个整数，不涉及堆分配。

**踩坑警告**：不要返回一个指向临时 `std::string` 的 `string_view`：

```cpp
std::string_view bad() {
    std::string s = "hello";
    return s;  // s 出作用域被销毁，sv 变成了悬垂指针
}
```

这和你笔记中"野指针"的本质是一样的——地址还在，指向的内容已经没了。

### `std::optional<T>` —— "可能为空"的安全指针语义

用 `T*` 来表达"有值或空"是不安全的——调用者可能忘记检查 `nullptr`。`std::optional<T>` 明确表达"要么有一个 `T`，要么没有"：

```cpp
std::optional<int> maybe_parse(const std::string& s) {
    if (s == "42") return 42;
    return std::nullopt;  // 表示"没有值"
}

auto val = maybe_parse("hello");
if (val.has_value()) {
    use(*val);  // 解引用，像指针一样
}
```

- 不涉及动态内存分配——`optional<T>` 里直接存了一个 `T`，只是在内部用一个布尔标志区分"有值"和"无值"。
- 它的语义比 `T*` 更精确：要么 `T` 要么空，没有"野指针""悬垂指针"这些隐患。
- 可以用 `value_or(default)` 安全地取值的默认值，替代了 `p ? *p : default` 这种三元表达式。

从指针视角看，`std::optional` 吸收了指针"指向一个对象或者为空"的语义，但去掉了指针"地址运算""类型转换""生命周期不明确"这些危险面。

### 结构化绑定（C++17）—— 从指针/迭代器对中优雅取值

结构化绑定不是指针相关的特性，但它最经典的用例之一恰好和处理指针相关返回值有关。

C++17 之前，往 `std::map` 里插元素：

```cpp
auto ret = m.insert({"key", value});
if (ret.second) {
    // 插入成功，*ret.first 是刚插入的迭代器
}
```

`std::map::insert` 返回的是一个 `std::pair<iterator, bool>`——本质上就是一个迭代器指针和一个布尔值的组合。你得记着 `.first` 是迭代器、`.second` 是是否成功。

C++17 结构化绑定：

```cpp
if (auto [iter, inserted] = m.insert({"key", value}); inserted) {
    // iter 直接就是迭代器
}
```

这没有引入新能力，但让"从容器API取一对值并判断"的语法变得像多返回值一样自然。它和你笔记中 `2[arr]` 那个例子是同一个道理——语法糖，编译后的结果一模一样，但读代码的人体验完全不同。

### `std::byte`（C++17）—— 操作原始内存的正确类型

操作原始内存（比如自己实现内存池或缓冲区）时，C++17 之前通常用 `char*`、`unsigned char*` 或 `void*`。问题是这些类型有"不该有的操作"——比如 `char*` 参与重载决议时会匹配到"字符串"语义。

`std::byte` 就是一个纯粹的"字节"类型：

```cpp
#include <cstddef>

std::byte buffer[1024];
// buffer 是一块原始内存，不暗示它是字符数组

// 只允许位运算
buffer[0] = std::byte{0xFF};
buffer[1] = buffer[0] >> 3;
// 不允许算术操作和隐式整数转换
```

- `std::byte` 不支持隐式转换为整数或字符，也不支持算术运算（`+` `-` `*` `/`）。
- 只支持位运算（`&` `|` `^` `~` `<<` `>>`）。
- 它代表了一块"纯粹的原始内存"，不隐含任何类型语义。

在指针视角下，`std::byte*` 是"我只知道这里有一块内存，但我不解释它是什么类型"的最准确表达——比 `void*` 更严格（不能隐式转换到其他指针类型）、比 `char*` 更纯粹（不暗示字符语义）。

### 小结：C++17 指针观

把上面这些放在一起，可以看到一条清晰的线索：**让指针回归它的本质工作，把"解释"和"安全"交给更高层的抽象。**

| 场景 | C++98 做法 | C++11/17 做法 | 改进点 |
|------|-----------|-------------|--------|
| 空指针 | `NULL` / `0` | `nullptr` | 类型安全，无重载歧义 |
| 动态内存 | `new` / `delete` | `unique_ptr` / `shared_ptr` | RAII，异常安全，不漏内存 |
| 只读传参（字符串） | `const char*` | `string_view` | 自带长度，不依赖 `\0` |
| 可能空的值 | `T*`（语义不明确） | `optional<T>` | 不分配堆内存，语义精确 |
| 原始内存操作 | `char*` / `void*` | `std::byte*` | 类型纯洁，无隐式转换 |

C++ 指针的门牌号模型没有变，也没必要变。现代 C++ 做的是在指针外面套上一层类型系统，让程序员少犯错——但当你透过这些抽象往底层看，底下还是那个"存了一个门牌号的变量"。


## 总结

- 指针就是装着地址的变量。类型决定了怎么解读那片内存、以及步长是多少。
- `&` 拿地址，`*` 顺着地址找内容。
- 数组名会退化成指针，所以 `[]` 和 `*` 本质相通。
- 动态内存分配迫使你面对指针，但智能指针把"谁负责释放"这件事自动化了。
- 引用是指针的上层封装（不可为空、不可改指向、语法更干净）。
- 函数指针是把代码也当作能寻址的数据。
- 多级指针是把指针自身也当作可寻址的数据。

如果能对着一张草稿纸画出几个方框，标上门牌号，箭头从指针框指向目标框，然后心算 `*p = 100` 时改的是哪个框——指针就已经被掌握了。引用、函数指针、多级指针不过是"内存地址"这个核心模型在不同场景下的自然延伸。
