## 一、除法运算的特殊性

### 整数除法

当被除数和除数都是整数时，除法运算结果为整数。

```cpp
int u = 10 / 2;  // 结果为 5，可以正确赋值给整型变量
```

此时编译器不会报错，输出结果符合数学运算规则。

### 除数为零的两种情况

**编译期错误**：直接写 `u = 10 / 0` 时，多数编译器会直接报错"被零除"（C2124 错误）。

**运行时错误**：当除数是变量且运行时值为零时（如 `u = 10 / t`），程序会直接崩溃。

```cpp
int t = 0;
int u = 10 / t;  // 运行时崩溃！
```

重要注意事项：
- 实际编程中必须判断除数是否为零，特别是当除数是变量时
- 业务逻辑中应添加条件判断：`if (t != 0) u = 10 / t;`
- 编译器无法检测运行时变量为零的情况，这类错误更危险

### 浮点数除法特性

- 浮点数运算不会自动四舍五入，会保留小数部分
- 与整数除法不同，浮点除法可以处理非整除情况
- 示例：`10.0 / 3.0` 结果为 `3.333...` 而非 `3`

## 二、浮点数运算的四舍五入问题

### 1. 浮点数转整数时的四舍五入问题

直接截断特性：浮点数转整数时会直接丢弃小数部分，不会进行四舍五入。

```cpp
int u = 1.1;  // u = 1
int v = 1.9;  // v = 1（也是 1，直接截断！）
```

业务逻辑处理：实际开发中需要四舍五入时，需自行添加判断逻辑。当小数部分大于等于 0.5 时加 0.5 进位，小于 0.5 时直接舍去。

```cpp
int u = 2 / 3;  // 结果为 0
int v = 4 / 3;  // 结果为 1
```

### 2. 整数相除时小数位的处理

运算规则：两个整数相除会先进行整数除法再赋值，导致小数位丢失。

```cpp
int x1 = 1, x2 = 2;
float f2 = x1 / x2;  // 结果为 0 而非预期的 0.5！
```

常见错误场景：视频播放进度计算等需要保留小数位的场景容易出现此问题。

错误本质：整数除法在运算阶段就已丢失精度，后续赋值给浮点变量无法恢复已丢失的小数部分。

### 3. 保证其中一个数为浮点数的方法

**有效方法**：

```cpp
f2 = x1 / (float)x2;  // 显式类型转换
f2 = 1 / 2.;          // 使用浮点字面量（注意小数点）
```

**无效方法**：

```cpp
(float)(x1 / x2)  // 仍会先进行整数除法！
```

工程实践：
- 推荐在运算前转换操作数类型
- 注意强制转换可能造成的精度损失需可控
- 实际开发中此问题是新手常见错误点
