# 理解 C++ 移动语义

> 前置阅读：[[理解C++指针]]、[[理解C++栈和堆]]
> 讨论基线：C++11 引入，C++17 强化（保证复制消除）

---

## 核心思想：偷，而不是复制

回顾 [[理解C++栈和堆]] 里的一个结论：`std::vector` 对象本身在栈上，它内部的数据在堆上；栈上只存了三个指针（`begin`/`end`/`capacity`）。

那么问题来了——把一个 `std::vector` 赋值给另一个，会发生什么？

```cpp
std::vector<int> a(1'000'000);   // a 在堆上分配了 400 万字节
std::vector<int> b = a;          // 拷贝：再分配 400 万字节，逐字节复制
```

如果 `a` 马上要被销毁，这种拷贝就是**纯浪费**——为什么不直接把 `a` 的堆指针"抢"过来，让 `a` 空手走人？

**移动语义做的事就是：转移资源的所有权，而不是复制资源本身。** 在"门牌号"模型下：

```
拷贝：  a: [门牌→房子A]    b: 另盖一座一模一样的房子B，b: [门牌→房子B]
移动：  a: [门牌→房子A] → b: [门牌→房子A]，同时把 a 的门牌号擦掉（置空）
```

拷贝要盖新房子、搬所有家具；移动只是**换个人拿同一把钥匙**，把原来的门牌擦干净。

## 两个前置概念：左值和右值

移动要能发生，编译器必须区分两类表达式：

- **左值（lvalue）**：有名字、可以取地址的表达式。比如变量 `a`、`v[0]`。
- **右值（rvalue）**：临时对象、即将销毁的表达式。比如字面量 `42`、函数返回的临时值。

```cpp
int a = 42;    // a 是左值
int b = a + 1; // a+1 是右值（临时结果，用完即毁）
```

关键点：**拷贝适合处理左值（我们可能还要继续用它），移动适合处理右值（反正要销毁了，不如偷走）。**

C++11 引入了**右值引用** `T&&`——它只能绑定右值，用来表达"这是个即将销毁的临时对象，你可以放心地偷它"：

```cpp
void take_ownership(std::string&& s);   // 只接受右值

take_ownership(std::string("hi"));      // OK，右值
std::string s = "hi";
take_ownership(s);                      // 编译错误！s 是左值
```

## `std::move` 的本质：一个"伪装的强制转换"

```cpp
std::string s = "hi";
std::string t = std::move(s);   // 把左值 s "伪装"成右值，从而触发移动
```

**`std::move` 本身不移动任何东西**——它只是把左值 `static_cast` 成右值引用，告诉编译器："请把 `s` 当作右值来对待"。真正搬家的逻辑在**移动构造函数**里。

> 类比：`std::move` 不是搬家公司，它只是给箱子贴了一个"可丢弃"标签。

这也是为什么 `std::move` 之后原对象仍可能存在——只是它的内容"合法但未指定"（valid but unspecified），通常是被置空了。

## 移动构造函数：偷指针 + 置空源

```cpp
class Buffer {
    int*  data_;
    size_t size_;

public:
    // 移动构造：偷走 other 的指针，再把 other 置空
    Buffer(Buffer&& other) noexcept
        : data_(other.data_),      // ① 拿走 other 的堆指针
          size_(other.size_) {
        other.data_ = nullptr;     // ② 把 other 的指针擦掉
        other.size_ = 0;           //    防止 other 析构时 delete 同一块内存
    }

    ~Buffer() { delete[] data_; }  // 只有 data_ 非空才真的持有内存
};
```

第二个赋值 `other.data_ = nullptr;` 是移动语义里**最容易漏的关键一步**。如果没有它，`other` 析构时会对同一块内存 `delete` 两次——**双重释放（double free）**，崩溃或未定义行为。

---

## 为什么必须 `noexcept`？

```cpp
Buffer(Buffer&& other) noexcept { ... }
```

`noexcept` 不是可选优化，而是 `std::vector` 扩容行为的分水岭：

```cpp
std::vector<Buffer> v;
v.push_back(Buffer(10));  // 触发扩容：要把旧数组搬到新数组
```

扩容时，`vector` 需要把已有的元素搬到新内存。它有两个选择：

- 如果移动构造是 `noexcept` → 放心用**移动**（快，偷指针）。
- 如果移动构造可能抛异常 → 回退用**拷贝**（慢，复制整个数据）。

为什么？因为移动会**破坏源对象**。如果搬到一半抛异常，源对象已经被破坏，无法回滚；而拷贝不会破坏源对象，可以安全回滚。标准库遵循"**强异常安全保证**"，所以对不承诺 `noexcept` 的类型宁可慢一点拷贝。

**规则：移动构造/移动赋值只要不抛异常，就一定标记 `noexcept`。** 否则你的 `vector` 可能一直在拷贝，性能优势全没了。

## `std::vector` 里的实战：偷堆指针

```cpp
std::vector<int> make_vec() {
    std::vector<int> v(1'000'000);
    // ...填充...
    return v;   // 移动（或直接 RVO），不拷贝百万个元素
}

std::vector<int> a = make_vec();        // ① 返回值：移动或 RVO
std::vector<int> b = std::move(a);      // ② 显式转移：b 偷走 a 的堆指针，a 变空
a.clear();                              // 安全：a 现在是空 vector
```

`vector` 的移动构造底层实现和你手写的 `Buffer` 一模一样：

```
移动前：  a 的栈上控制块: { data→堆块X, size=100万, cap=200万 }
移动后：  b 的栈上控制块: { data→堆块X, size=100万, cap=200万 }
          a 的栈上控制块: { data→nullptr, size=0, cap=0 }
```

堆块 X 从头到尾只有一个，只是"谁拿着它的门牌号"变了。**这就是 [[理解C++栈和堆]] 里说的"容器用移动语义偷走堆指针"的底层原理。**

## C++17 的强化：保证复制消除（guaranteed copy elision）

C++11/14 里，`return v;` 编译器可以优化成"直接在调用方构造"（RVO，return value optimization），但这是**允许的优化**——不优化也合法，可能仍发生一次移动。

C++17 把这个变成了**语言保证**：按值返回一个**纯右值临时对象**时，强制不发生拷贝也不发生移动，直接在目标位置构造：

```cpp
std::vector<int> f() {
    return std::vector<int>(1'000'000);   // 纯右值 → C++17 保证零拷贝零移动
}
```

这消除了很多过去需要 `std::move` 才能换来的性能。

## 移动语义的代价和边界

| 观点 | 说明 |
|------|------|
| 移动后源对象的状态 | "合法但未指定"——可以销毁、可以赋值，但别假设它还有值 |
| 移动并不总是更便宜 | 对 `int`、`double`、裸指针这种 trivially copyable 类型，移动和拷贝一样，别 `std::move` 它们 |
| 不是所有类型都支持移动 | 有自定义拷贝语义但没写移动构造的类型，`std::move` 会退化为拷贝 |
| `const T&&` 是反模式 | 移动构造函数签名里的 `&&` 不能是 `const`——const 意味着不能修改源对象去置空 |

---

## 总结

- **移动语义 = 转移资源所有权，而不是复制**：偷走堆指针、把源指针置空，避免大块数据的深拷贝。
- **两个机制配合**：右值引用 `T&&`（表达"可偷的临时对象"）+ 移动构造函数（实现偷）。
- **`std::move` 只是标签**：它不搬家，只是把左值伪装成右值，让编译器选择移动而非拷贝。
- **`noexcept` 是硬性要求**：没有它，`vector` 扩容会退化为拷贝，性能优势全丢。
- **C++17 保证复制消除**：按值返回纯右值时零拷贝零移动，这是语言层面的优化保证。
- **和指针笔记的关系**：移动操作的对象本质是"持有资源的指针"，移动就是对那个门牌号的交接。理解了指针和栈堆，移动语义就是在回答一个问题——"这块堆内存，到底归谁管？"
